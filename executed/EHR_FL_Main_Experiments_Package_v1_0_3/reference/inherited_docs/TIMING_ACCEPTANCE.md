# Repeated timing and application-payload pilot — counting clarification 1.0.2

## Frozen inherited workload

Source: `reference/pilot_run_matrix.csv` TIMING rows and
`reference/pilot_settings_v1_1.json` (`pilot`, `measurement`). These source files
contain older planning fields too; the accepted patched environment and approved
119-dimensional schema override only those explicitly documented obsolete fields.

Three matched repetitions, in this exact order: B then C; C then B; B then C.
Reference distribution only. Use the originally preselected 256 routine training
and 128 routine validation sessions per simulated client (768 / 384 overall).
Six rounds in each of six independent service runs; round 1 remains in training
and raw logs but is the predetermined warm-up exclusion from primary summaries.
Rounds 2–6 are measured, giving 30 measured fit rounds, NOT 30 independent trials.
There are 432 total local optimiser updates (360 after the warm-up exclusion) and
36 global aggregations. The same model-training seed 20260906, not the main seed
list, is used each run. Protocol keys/masks remain freshly OS-backed and unseeded.

The first five reference draws reproduce the previously used subset rule; round 6
is generated by the identical rule before measurements. No session is chosen by
its loss, anomaly score or threat label. This is deliberately the TIMING workload,
not another full-size training run or a model tuning stage. With only three pairs
and B-C occurring twice, residual ordering/thermal effects remain a limitation.

## Measured quantities and their limits

1. **Primary: instrumented server fit-workflow wall time**, measured by
   `perf_counter_ns()` from entry to exit of the stock fit workflow. Excludes
   installation (none), staging, unit tests, FAB preflight, service startup,
   identity handshake, initial evaluation, per-round evaluation and selected-model
   re-evaluation. It *includes* local loading inside the fit request, process/RPC
   overhead, training, numerical safety checks, identity checks, aggregation,
   checkpoint saving, instrumentation and small client metadata writes. It is
   NOT a pure cryptographic-compute time or uninstrumented production latency.
2. Evaluation workflow, outer round including evaluation, initial evaluation and
   selected checkpoint evaluation are separate spans. The outer interval contains
   nested intervals and is not added to them. Client wall times overlap; they are
   not summed to estimate server latency. Each client's fit wall and process CPU
   times are recorded; a client CPU sum is labelled as CPU, never latency.
3. All four C stages are timed, including their communication and relevant checks.
   Masked-vector collection includes local training. Unmask includes communication,
   reconstruction and the aggregate callback. It is not numerically equivalent to
   timing only Flower FedAvg's vector averaging in B. B additionally records native
   averaging and its independent numerical check separately. The independent
   oracle overhead in B is a disclosed instrumentation asymmetry, not subtracted
   from wall-clock measurements or called a security overhead by itself.
4. Data loading/checks and routine train/validation scoring are separately timed
   inside each client callback. One excluded warm-up round does NOT guarantee warm
   caches or eliminate fresh subprocess overhead on later messages.
5. **Communication accounting: application record-content bytes**, using the Flower
   1.22 `message_size_mod` logical-content convention. The 1.0.2 observer repairs
   native ConfigRecord handling of zero-length lists/scalar strings/scalar bytes:
   zero value-element bytes plus the original key length, without changing the
   transmitted record. Non-empty config entries and array/metric records retain
   native `count_bytes()` behaviour. `len(str)`/`len(key)` remains the legacy
   convention, not a claim of UTF-8 serialized byte accuracy. See
   `EMPTY_CONFIG_COUNT_FIX.md` and rule `flower122_record_content_zero_length_v1`.
   Count the request at the outer ClientApp boundary before identity fields are
   removed, and the response after identity/secure modifiers complete. Count all
   arrays, metrics and configs, including masked arrays carried as config bytes.
   Count client incoming + outgoing across all three clients only once. A matching
   server-side observer operates after identity addition/before removal solely to
   cross-check every request ID, node, phase and byte breakdown. Never add the
   server totals to the client totals. Global-model broadcast copies are counted
   separately because each client receives one.
6. These are NOT protobuf/gRPC/TCP/IP bytes. Message metadata, transport headers,
   retransmissions, control/heartbeat/FAB traffic and Flower storage/deduplication
   are not measured. No packet capture, firewall changes or elevated permissions.
   Report this measure under its precise name; full wire measurement remains open.
7. Sampled process-tree RSS at 0.05 seconds is inherited approximate diagnostics
   for the service lifecycle, not a precisely measured peak physical allocation.
   Shared pages can be counted repeatedly and transient/unreadable children can
   be missed by the inherited sampler. This is not a Windows-wide memory metric
   or a train-only RAM limit. Memory is not the primary acceptance endpoint here.
8. Inference microbenchmarks and the extra-seed sanity rows are not run by this
   package. They remain separate planned work, as does any validation of main
   experiment settings. No training improvements are inferred from the timing run.

## Acceptance (not a performance target)

Require the prior full-size report and accepted patched environment identities;
unchanged schema/scaler; exact original subset and six-round draw replay; no train/
validation session overlap; all runtime tests with no failures/skips; all six
native FAB builds and relocated loads; successful identity probes; all clients
and rounds; existing FedAvg and SecAgg+ numerical/cohort/range guards; valid finite
model/evaluation; local-only service listeners; successful shutdown/port rebind;
integer nonnegative timing intervals with completed spans; no missing/duplicate
client counters; exact paired boundary byte reconciliation; all predeclared runs
in order; unchanged input artefacts and environments after completion.

Any protocol failure still aborts; measurement code cannot mask an exception or
turn it into PASS. Partial attempts are preserved but never silently included as
successful repetitions. No automatic run retry, dropped slow observation, timing
threshold or optimistic report made from an incomplete set.

## Analysis fixed before target-host timings

Keep round 1 and rounds 2–6 in `all_round_measurements.csv`. For each run compute
the median of rounds 2–6 for fit workflow, evaluation workflow, outer round and
fit record-content bytes. For each of the three matched B/C pairs report B, C,
C−B and `100*(C−B)/B`; mark undefined if B<=0. Across the three pairs report the
observations, mean/median, sample SD, min/max and descriptive coefficient of
variation where defined. No p-values, confidence intervals, equivalence claims,
or treatment of the 30 dependent round measurements as 30 independent trials.
A large or negative measured overhead is an outcome, not a reason to change/drop
runs. Keep B's and C's training data, initialisation and budgets matched.

## Security and reproducibility scope

Reuse the accepted `1.22.0+mai.prg7570.1` build without installation or further PRG
changes. HMAC code, key generation, quantisation, source binding and no-fallback
cohort controls remain unchanged. Instrumentation exports scalar sizes/times and
public phase labels/identifiers only, never message contents, raw updates, C update
hashes, protocol keys, masks or shares. Client logs are read by the trusted research
operator after services stop; the ServerApp does not read them. The shared host,
unencrypted loopback network and evaluation summaries retain their known limits.
Neither this pilot nor scope approval constitutes privacy certification. Main
experiments and both final test partitions remain closed.
