# 1.0.1 metadata-fixture fix

## Root cause and scope

The target host ran 285 unit cases: 278 successful cases, seven errors, zero
assertion failures and zero skips. All seven errors attempted assignment to
`Metadata.message_id`, which has no setter in Flower 1.22.0. The four assignment
sites are in `tests/test_integration_identity.py` (two) and
`tests/test_measurement.py` (two); multiple cases shared the same helper.
This happened during the required native test suite, before any of the six
scheduled timing Deployment runs. Some independent native FAB/public-vector
checks ran inside the unit suite; those are not timing-run results.

## Repair

The fixture creates a NEW received instruction with a `Metadata` instance via
Flower 1.22's internal `Message(metadata=..., content=...)` constructor. This is
explicitly an in-memory transport substitute restricted to tests. No setter is
added, no private metadata is overwritten and no message ID is generated by
production instrumentation. Existing IDs are preserved; replacing one is an
error. The source message and mutable payload are not shared with the received
copy. Reply correlation follows Flower's native `reply_to` behaviour.

All 100 protected source/configuration/policy files from 1.0.0 remain identical:
app/, config/, scripts/, fullsize_support/, timing_support/, validation_support/,
reference/, and TIMING_ACCEPTANCE.md. This includes the PRG correction, native
workflow, counters, clock boundaries, round limits, seed, sampling schedule,
warm-up rule, abort/zero-skip criteria and network-listener checks.

## Verification and limitations

23 new regressions cover a strict read-only stand-in contract (12), source-boundary
checks (3), and actual Flower constructor/correlation/duplicate/missing-ID checks
(8). Original native identity and measurement cases remain mandatory.
The corrected target suite has 308 cases. Local preparation without Flower:
281 passed; 27 native cases skipped and therefore status INCOMPLETE, not a full
validation pass. These numbers are not security certifications or independent
empirical experiments. On the user host any skip/error/failure still aborts.

The host-side environment is NOT recreated or modified; the accepted patched
Python is reused. A new run directory is created. The failed timing attempt is
retained and is not a timing observation or a successfully completed repeat.

No reference/payload values, trial ordering, datasets or privacy claim are
changed. No final-test data or measured B/C deployment were used in this repair.
Preparation can validate fixtures/logic, but native tests and deployment must
still pass on the installed candidate Flower environment.
